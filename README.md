# More Good Days — Lite

> 남은 날을 세는 앱이 아니에요.
> 좋은 날을 늘리는 앱입니다.

만성질환이나 노령기를 함께 지나는 반려동물의 하루를, **10초 안에** 남겨 두는 앱.
기록이 모이면 흐름이 보이고, 병원에서 할 말이 생깁니다.

이 저장소는 그 제품의 **가장 작은 완결형**입니다. 아이를 등록하고, 매일
다섯 번 눌러 기록하고, 홈에서 이번 주가 어땠는지 본다 — 딱 그만큼.

**→ https://mgds-mvp-lite.vercel.app**

계정도 설치도 필요 없습니다. 열면 바로 시작하고, 기록은 그 브라우저에만
남습니다.

---

## 무엇을 만들지 않았는가

이 앱에는 흔한 기능 몇 가지가 **일부러** 없습니다. 빠뜨린 것이 아니라
넣지 않기로 한 것입니다.

| 없는 것 | 이유 |
|---|---|
| 연속 기록 일수 · 스트릭 | 하루 빠뜨린 것이 실패로 보이면, 힘든 날에 앱을 열지 않게 됩니다 |
| 빨간색 경고 | 팔레트에 빨강이 아예 없습니다. 쓰려고 해도 쓸 수 있는 색이 없습니다 |
| "어제 기록이 비어있어요" | 지적하지 않습니다. 미완료는 **행동 버튼**으로만 말합니다 |
| 힘든 날 개수 | 좋은 날만 셉니다. 힘든 날은 세는 대신 고맙다고 말합니다 |
| 남은 날 · 카운트다운 | 매일 하나씩 **올라가는** 숫자만 있습니다 (함께한 N일) |
| 점수 · 등급 · 진단 | 기록을 돕는 도구입니다. 판정하지 않습니다 |

이 규칙들은 약속이 아니라 **검사**입니다. `npm run lint:principles` 가
금지 표현, 한글 문구의 위치, 빨간 계열 색, 힘든 날 집계 코드를 막습니다.
어기면 빌드가 아니라 원칙 검사에서 먼저 걸립니다.

## 화면 여섯 개

```
/                인트로를 봤는지 · 아이가 있는지 · 고지를 했는지로 갈래를 정한다
   ↓
/intro           인트로 3장 — 확정 카피. 건너뛸 수 있다
/pet/new         아이 등록 — 이름과 나이만 있으면 시작한다. 사진은 건너뛸 수 있다
/welcome         마무리 1장 + 의료 고지 1회. 여기는 건너뛸 수 없다
/today           홈 — 사진 · 함께한 N일 · 이번 주 좋은 날 · 오늘 기록 · 점 일곱 개
/today/:date     기록 — 카드 5장. 다섯 번 누르면 저장까지 끝난다
/pet/backup      내보내기 · 가져오기
```

**탭바가 없습니다.** 한 방향으로만 흐르고, 돌아오는 곳은 늘 홈입니다.

### 기록이 10초인 이유

카드 다섯 장에 확인 버튼이 없습니다. 선택지를 누르면 곧바로 다음 장이고,
**다섯 번째 탭이 저장**입니다. 태그와 메모는 저장된 **뒤에** 나오는 선택
항목이라 탭 수에 들어가지 않습니다.

`tests/daily-log-cards.test.ts` 가 이 계약을 붙잡습니다 — 카드에 "다음"
버튼을 넣으면 테스트가 깨집니다.

### 힘든 날에 일어나는 일

하루 전체를 `힘든 날` 로 고르면 저장 직후 이 문장이 나옵니다.

> 기록해주셔서 고맙습니다.
> 힘든 날을 남기는 것도 돌봄입니다. 이 기록이 병원에서 쓰입니다.

100% 노출입니다. 조건도 확률도 없습니다. `scripts/lint-thanks.mjs` 가
이 문구가 제자리에 있는지 검사합니다.

## 데이터는 이 기기에만 있습니다

계정도 서버도 없습니다. 기록은 브라우저의 IndexedDB 에만 저장되고, 어디로도
전송되지 않습니다.

그래서 **첫 기록 직후 백업 파일이 자동으로 한 번 떨어집니다.** 홈 맨 아래의
`기록을 파일로 내보내기` 로 언제든 다시 받을 수 있고, 같은 화면에서 되돌릴
수도 있습니다. 이 앱에서 데이터를 잃는 유일한 경로는 브라우저 저장소를
지우는 것입니다.

|---|---|
| `npm run dev` | 개발 서버 |
| `npm test` | 단위 테스트 |

개발 서버에서만 열리는 보조 화면이 있습니다.

| 경로 | |
|---|---|
| `/dev/ui` | 공용 UI 부품 카탈로그 |
| `/dev/seed` | 시드 데이터 생성 · 초기화 |
| `/dev/state` | IndexedDB 덤프 |

프로덕션 빌드에는 이 청크가 만들어지지 않습니다.

## 배포

**https://mgds-mvp-lite.vercel.app** — `main` 에 push 하면 Vercel 이 자동
배포합니다. 다른 브랜치와 PR 은 프리뷰 URL 이 따로 생깁니다.

- Vercel **Root Directory 는 기본값(`./`)** 입니다. 저장소 루트가 곧 앱
  루트이므로 여기에 하위 폴더 이름을 넣으면 빌드가 실패합니다.
- Framework Preset 은 `Vite` 자동 감지. **환경 변수는 없습니다.**
- `vercel.json` 의 rewrite 가 SPA 딥링크를 처리합니다. **이걸 지우면
  `/intro` 를 직접 열기와 새로고침이 404 가 되고, 특정 날짜의 기록 화면을
  링크로 공유할 수 없게 됩니다.**
- 배포는 `npm run build` 를 그대로 씁니다 — 타입 검사와 번들 예산 검사가
  그 안에 있어 **예산을 넘기면 배포가 실패합니다.** 의도한 동작입니다.
- 커스텀 도메인은 범위 밖이고 `*.vercel.app` 기본 URL 로 운영합니다.

배포 확인은 네 가지를 봅니다. 셋은 브라우저에서, 하나는 실기기에서만 됩니다.

| | 무엇 | 통과 기준 |
|---|---|---|
| 1 | 첫 진입 | 인트로 1장이 뜬다 |
| 2 | `<URL>/intro` 직접 열기 · 새로고침 | 404 가 아니다 (rewrite 확인) |
| 3 | `<URL>/dev/ui` | **카탈로그가 아니라 앱으로 튕긴다** (개발 라우트가 번들에 없음) |
| 4 | 기록 완주 후 다운로드 폴더 | `mgds-backup-*.json` 이 실제로 있다 — 아래 참고 |

**4번은 실기기에서만 확인됩니다.** 첫 기록 직후의 자동 백업은 사용자 조작
없이 시작되는 다운로드이고, iOS Safari 는 그것에 엄격합니다. 데스크톱에서
되는 것이 실기기에서 된다는 뜻이 아닙니다. 이 앱에서 데이터를 지키는 유일한
장치라 여기가 막히면 백업을 사용자가 직접 누르는 흐름으로 바꿔야 합니다.

## 작업 규칙

`main` 에 **직접 push 해도 됩니다.** 라이트 버전이라 PR 을 강제하지 않습니다.

다만 `main` 룰셋에 **CI 필수 상태 검사**가 걸려 있습니다
(`test · lint:principles · build`). 저장소 admin 은 우회할 수 있으므로 관리자
입장에서는 직접 push 가 그대로 되고, 그 외에는 검사가 통과한 커밋만
`main` 에 올라갑니다.

CI 는 push 와 PR 양쪽에서 돌고, 로컬에서 미리 같은 것을 돌릴 수 있습니다.

```bash
npm run typecheck && npm run lint:principles && npm run test:coverage && npm run build
```

**CI 잡 이름을 바꾸지 마세요.** GitHub 이 보고하는 상태 검사 이름은 워크플로
이름이 아니라 **잡 이름**이고, 그 문자열이 룰셋의 필수 검사 이름입니다.
바꾸면 룰셋이 없는 검사를 기다리게 되어 `main` 이 잠깁니다. 이유는
`.github/workflows/ci.yml` 주석에.

## 구조

```
src/
├─ app/         라우팅 · 진입 관문(RootGate) · 개발용 화면
├─ copy/        ko.ts — 화면에 나가는 모든 문구가 이 파일 하나에
├─ config/      risk-tags.json — 병원 연락을 권할 태그
├─ data/        Dexie 스키마 · Repo · 내보내기
├─ domain/      순수 함수. import 문이 하나도 없다
├─ features/    intro · pet · welcome · home · daily-log · backup
└─ ui/          디자인 토큰 + 공용 부품 8개
```

지켜야 하는 두 가지가 구조에 박혀 있습니다.

- **문구는 `copy/ko.ts` 에만 있습니다.** 화면 코드에 한글을 적으면
  `lint:hangul` 이 막습니다. 이 파일 하나만 읽으면 제품의 모든 말을
  감수할 수 있어야 하고, 수의사 감수가 그래서 가능해집니다.
- **`domain/` 은 아무것도 import 하지 않습니다.** 시간을 알아내는 유일한
  통로는 인자로 받는 `now` 입니다. 날짜·좋은 날 계산의 정확도가 이 제약에서
  나옵니다.

### 하루의 경계는 04:00 입니다

밤 11시에 남긴 기록과 새벽 2시에 남긴 기록은 **같은 날**입니다.
`[00:00, 04:00)` 은 전날로 셉니다 — 아픈 아이를 돌보는 밤은 자정에 끝나지
않습니다. 바꿀 곳은 `src/domain/dates.ts` 의 `NIGHT_CUTOFF_HOUR` 하나입니다.

## 감수 전인 것

- **위험 태그가 `구토`·`헐떡임` 둘뿐입니다.** 태그를 하나 더하는 것은
  "이 증상을 보면 병원에 연락하라"고 제품이 말하는 것과 같습니다.
  임상 판단이라 임의로 넣지 않았습니다 — `src/config/risk-tags.json` 참고.
- **색상 팔레트와 일러스트는 자리표시자입니다.** 인트로 3장의 그림 자리에
  지금은 도형만 있습니다. 색은 `src/ui/tokens.css` 한 곳만 고치면 됩니다.

## 이 저장소와 본 MVP

본 MVP(`mgds_mvp`)는 33개 단위 계획 중 11개까지 진행된 상태이고, 흐름 탭 ·
약 관리 · 진료 요약서 · 알림 · 계정 · 동기화가 그 뒤에 있습니다.

이 라이트 버전은 그 코드에서 **동작하는 부분만 골라내 완결시킨 것**입니다.
데이터 계층과 도메인 함수는 본 MVP 와 같고, 화면만 여섯 개로 줄였습니다.
빠진 기능을 `disabled` 버튼으로 남겨 두지 않은 것이 라이트의 규칙입니다 —
누를 수 없는 버튼은 아직 없는 기능을 매일 가리킵니다.
