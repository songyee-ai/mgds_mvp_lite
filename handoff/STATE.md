## 5. 이미 밟은 함정 — 다시 밟지 마세요

- **grid 의 `1fr` 은 `min-height` 로 풀리지 않습니다.** 컨테이너 높이가
  `auto` 로 남아 `1fr` 이 내용 크기로 떨어집니다. 그림 칸이 0px 이 되고
  185px 이 넘쳤습니다. → `height` 를 줘야 합니다.
- **`height: 100%` 는 grid/flex 자식에서 해소되지 않습니다.** 칸은 422px
  인데 SVG 가 195px 이었습니다. → 절대 위치로 채웁니다.
- **`aspect-ratio` + `max-width` 로는 정사각이 안 됩니다.** 높이가 확정값이면
  폭이 잘려도 높이는 안 돌아옵니다 (343×392가 나왔습니다).
- **grid 의 첫 아이는 첫 열에 놓입니다.** 로고가 중앙에서 124px 왼쪽에
  섰습니다. 가운데 열을 명시해야 합니다.
- **flex 는 자동 여백을 `flex-grow` 보다 먼저 해소합니다.** `margin-top: auto`
  가 남는 세로를 다 먹어 그림이 안 자랐습니다.
- **React 는 `muted` 를 어트리뷰트로 남기지 않습니다.** iOS Safari 가 자동
  재생 자격을 어트리뷰트로 보는 경로가 있어 `setAttribute('muted','')` 를
  함께 합니다.
- **iOS 는 `preload="auto"` 를 무시합니다.** 자동 재생까지 막히면 프레임이
  한 장도 디코딩되지 않아 화면이 빕니다 → 포스터 이미지가 그 답입니다.
- **iOS 의 「동작 줄이기」가 `prefers-reduced-motion` 입니다.** 흔하게 켜져
  있습니다. 정지 화면으로 나오는 것은 고장이 아닙니다.
- **`box-sizing: border-box` 가 iOS 의 날짜 칸을 잡지 못합니다.** `*` 에
  이미 걸려 있는데도 `input[type=date]` 가 카드 밖으로 튀어나왔습니다
  (아이폰, 글자 칸은 멀쩡). iOS 가 기본 모양을 입히면서 `width` 계산 **밖에서**
  내부 여백을 더합니다 → `appearance: none`. 선택기는 그대로 뜹니다.
- **`canvas.toBlob` 은 모르는 형식을 거절하지 않습니다.** 조용히 PNG 를
  돌려줍니다. `blob.type` 을 확인하지 않으면 "300KB 이하"가 소리 없이
  깨지고, 확인하고 던지면 **사진을 통째로 잃습니다.** 확인하고 **다음
  형식으로 내려가는 것**이 답입니다 (`features/pet/photo.ts`).
- **디코더가 둘이고 서로 다릅니다.** `createImageBitmap` 이 실패해도
  `<img>` 로는 열리는 파일이 있습니다 (iOS 의 HEIC). 한 길만 두면 그
  사진은 영영 안 담깁니다.

## 7. 열린 항목

### 자동 백업 — ✅ 아이폰 Safari 에서 확인되었습니다

**2026-09-13 사용자 확인 (아이폰 Safari): 두 경로 모두 파일이
만들어집니다.** 기록 5탭을 마치면 태그 화면이 뜨기 전에 json 이 자동으로
떨어지고, `백업 파일 받기` 를 눌러도 json 이 떨어집니다.

**이 저장소에서 가장 오래 열려 있던 항목이 이걸로 닫혔습니다.** iOS 가
사용자 조작 없는 내려받기를 막을 것이라는 우려가 근거였는데, 막지
않았습니다.

> **그래도 안전망은 그대로 둡니다.** 확인된 것은 이 기기 · 이 iOS
> 버전뿐이고, 앱은 여전히 자동 내려받기의 성공 여부를 알 수 없습니다.
> 안전망은 그 모름을 사용자의 손가락으로 지우는 장치이지, iOS 하나를
> 겨냥한 임시방편이 아닙니다.

**파일이 둘 생기는 것은 최초 1회뿐입니다.** 자동은 `auto_backup_at` 이
남으면 다시 시도하지 않고, 안전망은 `backup_saved_at` 이 있으면 나오지
않습니다. 한 번 받은 뒤로는 **기록해도 파일이 하나도 생기지 않습니다.**

사용자 조작 없이 시작되는 다운로드는 브라우저가 조용히 막을 수 있고,
막아도 `a.click()` 은 예외를 던지지 않습니다. 그래서 `auto_backup_at` 은
**"시도한 시각"일 뿐 성공이 아닙니다.** 그 구멍을 안전망이 메웁니다
(`src/features/backup/safetyNet.ts`).

- 기록을 저장한 화면 맨 아래에 `백업 파일 받기` 카드 한 장.
  **직접 받은 파일이 하나도 없는 동안만** 나오고, 한 번 받으면 영영
  사라집니다. `backup_saved_at` 이 그 판정입니다.
- `/pet/backup` 의 수동 내보내기도 `backup_saved_at` 을 남깁니다.
- 두 키를 나눈 이유가 전부입니다 — `auto_backup_at` 으로 안전망을 끄면
  자동이 막힌 기기에서 백업이 **하나도 없게** 됩니다.
  `tests/data-export.test.ts` 의 「자동 백업이 시각을 남겼어도 안전망은
  그대로 나온다」가 이것을 붙잡습니다.

> **⚠️ 클릭 처리기 안에서 `await` 하지 마세요.** `downloadBlob` 앞에
> `await` 가 하나라도 있으면 사용자 활성화 창이 닫힌 뒤에 내려받기가
> 불릴 수 있고, 그러면 자동 백업과 **똑같은 자리에 다시 섭니다.**
> 그래서 `prepareBackup` 이 화면이 뜰 때 Blob 을 미리 만들어 두고,
> 클릭 처리기는 기다리는 것 없이 건네기만 합니다.

**왜 이 기능이 있는가** (TECH_SPEC 8-6, 이 결정의 전부입니다)

> Safari 는 사용자 상호작용 없이 7일이 지나면 스크립트가 쓴
> 저장소(IndexedDB 포함)를 삭제할 수 있습니다.

**사용자가 아무것도 하지 않아도 사라진다**는 뜻입니다. 캐시를 지워서가
아니라 일주일 안 열어서. 매일 쓰는 사람에게는 안 생기지만, **노령기
보호자가 며칠 정신없이 보내는 상황이 이 제품이 정확히 겨냥하는
상황입니다.** 그래서 보호자가 백업이라는 것을 배우기 전에 백업이 이미
있어야 하고, 그것이 "첫 기록 직후 한 번"인 이유입니다.

**같은 항목이 말하길, 홈 화면에 추가된 웹앱은 이 정책에서 제외됩니다.**
매니페스트와 아이콘이 들어갔고(4-5), 설치를 권하는 자리도 2026-09-13 에
들어갔습니다(4-6). **7일 규칙을 되돌리는 것이 백업이라면, 애초에 겪지 않게
하는 것은 설치입니다** — 8-6 에서 설치가 1번이고 백업이 2번인 이유입니다.

> **문구에서 소실을 위협으로 쓰지 마세요** (TECH_SPEC 8-6 대응 1번).
> "홈 화면에 추가하면 알림이 오고, 기록이 안전하게 남아요" 쪽입니다.
> 라이트에는 알림이 없어 그 절반만 씁니다. 자세한 것은 4-6.

### 확인하면 좋은 것

- **아이폰 홈 화면에 추가했을 때 아이콘이 제대로 보이는지.** 브라우저
  탭·매니페스트는 로컬에서 확인했지만 iOS 의 모서리 깎기는 실기기에서만
  보입니다 (4-5 참고).
- **파비콘용 그림이 오면 `favicon-16/32` 만 갈아 끼웁니다.** 홈 화면
  아이콘은 건드리지 않습니다 — 서로 다른 그림입니다 (4-5 참고).
- 사진 업로드 실기기 — 아이폰 HEIC, 세로 사진이 눕는지, 화면의 `NNKB` 가
  300 이하인지
- 영상이 **960px** 이라 처음 규격(1440)보다 작습니다. Pro Max 급에서 약간
  부드럽게 보입니다. 선명하게 가려면 1440 으로 다시 뽑아 같은 명령으로
  재인코딩하면 됩니다.

## 8. 도구 메모

**ffmpeg 는 이 머신에 설치되어 있지 않습니다.** 영상·이미지를 손봐야 하면
둘 중 하나입니다.

```bash
# 임시로 (시스템을 건드리지 않음)
mkdir -p /tmp/ff && cd /tmp/ff && npm init -y && npm i ffmpeg-static
# → node_modules/ffmpeg-static/ffmpeg.exe

# 영구 설치 (Windows 11)
winget install --id Gyan.FFmpeg -e --accept-source-agreements --accept-package-agreements
```

로고 자산을 다시 만들 때:

```bash
ffmpeg -i logo.png -vf "crop=1342:719:128:240,scale=720:-1:flags=lanczos" \
  -c:v libwebp -quality 88 logo.webp
```

`crop` 값은 알파 채널의 실제 경계입니다 (원본 1536×1024 에서 여백을 뺀 것).

**PNG 크기 조정·합성은 아무것도 설치하지 않고 됩니다.** Windows 의
`System.Drawing` 이면 충분합니다. 아이콘 5장은 그렇게 만들었습니다.

```powershell
Add-Type -AssemblyName System.Drawing
# FromFile · Graphics.DrawImage(dst, src, GraphicsUnit::Pixel) · Save(…, Png)
# InterpolationMode 를 HighQualityBicubic 로 두지 않으면 작은 크기에서 뭉갭니다.
```

> ⚠️ **PowerShell 5.1 은 BOM 없는 UTF-8 `.ps1` 을 ANSI 로 읽습니다.**
> 스크립트 안에 한글 경로(`파비콘.png`)를 적으면 깨져서
> `Illegal characters in path` 가 납니다. 원본을 ASCII 이름으로 복사해
> 두고 쓰는 것이 빠릅니다.

원본 두 장 모두 1254×1254 이고 사용자 제공입니다.

**워드마크(홈 화면 아이콘)** — 불투명 RGB, 배경 `#748C6B`, 내용이 가로
83% · 세로 65%. **손댈 것이 없습니다.** 크기만 줄이면 되고, 알파가 한
픽셀도 없는지만 확인하면 됩니다 (iOS 는 투명한 자리를 검게 둡니다).

**배지(파비콘)** — RGBA, 원의 중심 `(625, 626)`, 실한 반지름 **420**,
그 바깥 약 15px 이 부드러운 헤일로. 파비콘은 한 변 **870** 으로 잘라
투명 그대로 씁니다.

> 배지를 **불투명 아이콘으로** 쓸 일이 다시 생기면 헤일로를 지워야
> 합니다. 평평한 초록 위에 그대로 얹으면 **옅은 고리로 남습니다.**
> 반지름 **415** 로 클립하고 나머지를 `#788C6E` 로 채우면 원 속 초록과
> 같은 색이라 자국이 안 보입니다. 채우는 색이 **2~3/255 만 달라도**
> 고리가 다시 보입니다 — `#798B6F` 로 두었을 때 실제로 그랬습니다.
